# 要件定義

> 機能ID（F-xx）はほかの設計書から参照される。一覧は [docs/README.md](README.md)

## プロジェクトの背景
- スクール（RaiseTech）の課題として作る。
- 課題のねらいは、**要件定義 → 設計 → 実装 → 公開 → 運用** という開発の流れを、小さなアプリで一通り経験すること。
- 題材にはタスクボード（カンバン方式）を選んだ。機能が少なく、画面（HTML / CSS / JavaScript）・サーバー・データベースの基本がひととおり使えるため。
- 練習で終わらせず、**本物のデータベースを使い、インターネットに公開して自分で使い続ける**ところまでやる。

## 目的とゴール
| 区分 | 内容 |
|------|------|
| 目的 | やることを忘れないように、ひとつの画面でまとめて見られるようにする。PCでもスマホでも同じ内容を見られるようにする |
| 学習のゴール | 要件定義書・設計・実装・公開・運用をひとりで最後までやりきる |
| 完成の目安 | [受け入れ基準](07_acceptance-criteria.md)をすべて満たし、インターネット上で公開して使えている |

## 利用者と利用環境
| 項目 | 内容 |
|------|------|
| 利用者 | 自分ひとり（複数の利用者には対応しない） |
| 主な端末 | PC（Mac）。スマートフォンからも使う |
| 対象ブラウザ | Google Chrome 最新版（必須）／ Safari 最新版（必須：スマホで使うため） |
| ネット接続 | 必要（データはサーバーのデータベースに保存するため） |
| 公開先 | サーバー：Render ／ データベース：Neon（[技術選定](06_tech-stack.md) 参照） |

## 用語の定義
| 用語 | 意味 |
|------|------|
| ボード | 3つの列がならんだ画面全体 |
| 列 | カードの状態を表す枠。「やること」「進行中」「完了」の3つ |
| カード | 1件のタスク。タイトル（文字）を1つだけ持つ |
| フロントエンド | ブラウザで動く部分（画面） |
| バックエンド（サーバー） | インターネット上で動き、画面からの依頼を受けてDBを読み書きするプログラム |
| API | 画面がサーバーに依頼するときの窓口（URLと送るデータの決まり） |
| DB（データベース） | データを保存しておく場所。今回は PostgreSQL を使う |
| ベーシック認証 | ブラウザ標準の、ユーザー名とパスワードを入れる画面でログインするしくみ |

## 機能要件

### 機能一覧
| ID | 機能 | 優先度 |
|----|------|--------|
| F-01 | ボード（3列）を表示する | 必須 |
| F-02 | カードを追加する | 必須 |
| F-03 | カードをとなりの列へ動かす | 必須 |
| F-04 | カードを削除する | 必須 |
| F-05 | データをDBに保存し、どの端末から開いても同じ状態を表示する | 必須 |
| F-06 | 列ごとのカード枚数を表示する | あれば良い |
| F-07 | ログイン（自分以外は使えないようにする） | 必須 |
| F-08 | 通信に失敗したことを知らせる | 必須 |

### 機能の詳細

**F-01 ボード表示**
- 左から「やること」「進行中」「完了」の3列をならべる。
- 列の中のカードは、追加した順（古いものが上）にならぶ。移動してきたカードは一番下。
- カードがない列には「カードはありません」と表示する。
- 読みこみ中は「読みこみ中…」と表示する。

**F-02 カード追加**
- 入力欄にタイトルを入れて「追加」ボタンを押すか、Enterキーを押すと追加される。
- 追加先は必ず「やること」列の一番下。
- タイトルのルール（画面とサーバーの両方でチェックする）：
  - 前後の空白は取りのぞく。
  - 空白だけ・何も入力していないときは追加しない（M-01を出す）。
  - 最大50文字。絵文字も1文字と数える（★50文字で足りるか）。
- 追加に成功したら入力欄を空にし、続けて入力できるよう入力欄にカーソルを残す。
- 失敗したときは入力欄の文字を消さない（もう一度追加できるように）。

**F-03 カード移動**
- 各カードに「←」「→」ボタンをつける。
- 「→」で右の列、「←」で左の列へ1つ動く。完了から「←」で進行中に戻せる。
- 「やること」のカードには「←」、「完了」のカードには「→」を表示しない。
- 動かしたカードは、移動先の列の一番下に入る。
- となりでない列（やること → 完了など）への移動は、サーバーでも受けつけない。

**F-04 カード削除**
- 各カードに「削除」ボタン（×）をつける。
- 押すと確認ダイアログ（M-02）を出し、「OK」のときだけ削除する。
- 削除したカードは元に戻せない。

**F-05 保存と表示**
- 追加・移動・削除のたびに、すぐにサーバーへ送ってDBに保存する（保存ボタンはない）。
- 保存に成功したら、DBから一覧を読みなおして画面を作りなおす（画面とDBがずれないようにする）。
- ページを開いたときはDBから読みこむ。PC・スマホ・別のブラウザのどれから開いても同じ内容になる。

**F-06 枚数表示**
- 列の見出しの横に枚数を出す。例：「やること（3）」

**F-07 ログイン**
- ページを開くと、ブラウザ標準のログイン画面（ユーザー名・パスワード）が出る。
- ユーザー名とパスワードは1組だけ。サーバーの設定（環境変数）に持たせ、プログラムやGitには書かない。
- ログインしていないと、画面もAPIも使えない。
- ブラウザを閉じるまではログインしたまま。

**F-08 通信エラーの表示**
- サーバーに届かない・保存に失敗したときは、M-04 / M-05 を赤字で表示する。
- 通信中は二重に操作されないよう、ボタンを押せなくする。

## 作らないもの（対象外）
| 内容 | 理由 |
|------|------|
| 複数の利用者（ユーザー登録・利用者ごとのデータ分け） | 自分ひとりで使うため |
| ログアウトボタン・パスワード変更画面 | ベーシック認証のしくみ上むずかしいため。パスワード変更はサーバーの設定で行う |
| ほかの人との共有 | 自分ひとりで使うため |
| 同時に開いた別の画面への自動反映 | 別の端末で変えた内容は、開きなおすと反映される。リアルタイムにはしない |
| カードのタイトル編集 | 最初の版では削除して作り直す運用とする（★次の版の候補） |
| 期限・担当者・メモ・ラベル | 機能を最小限にするため |
| 列の追加・名前変更 | 3列で固定 |
| 列の中での並び替え・ドラッグ＆ドロップ | ボタン操作で十分なため（★次の版の候補） |
| オフラインでの利用 | DBに保存するため、ネット接続が前提 |

## 非機能要件
機能以外で「こうなっていてほしい」条件です。

| 区分 | 要件 |
|------|------|
| 使いやすさ | 説明を読まなくても、見ただけで追加・移動・削除の方法がわかる |
| 使いやすさ | マウスだけでなく、キーボード（Tab・Enter）でも全部の操作ができる。操作後もフォーカスが迷子にならない |
| 表示 | 画面幅 768px 以上では3列を横にならべ、それより狭いときは縦にならべる |
| 性能 | カードが100枚あっても、操作してから画面が変わるまで1秒以内（サーバーが起きているとき） |
| 安全性（通信） | HTTPS で通信する（公開先が自動で対応） |
| 安全性（ログイン） | パスワードは環境変数に置き、Gitに入れない。本番でパスワードが未設定ならサーバーを起動しない |
| 安全性（入力） | 入力された文字をHTMLとして読みこまない（`textContent` を使う）。SQLは値を直接つなげず、プレースホルダ（`$1`）で渡す |
| 安全性（DB） | DBとの通信は暗号化する（`sslmode=require`） |
| データ | カードのデータはDBに保存する。サーバーやブラウザを閉じても消えない |
| 保守性 | 画面・API・DBの読み書きをファイルごとに分ける。SQLは1つのファイルにまとめる |
| テスト | APIの自動テストを用意し、変更したら `npm test` がすべて通ってから公開する |
| 費用 | 無料の範囲で運用する |

### 運用について
| やること | タイミング |
|---------|-----------|
| 動いているか確認（`/api/health`） | 使うとき |
| エラーの確認（Render のログ） | おかしいとき |
| バックアップ（`pg_dump`） | 月1回 |
| ライブラリの更新とテスト | 月1回 |
| パスワード変更 | 漏れたかもしれないとき |

具体的な手順は `README.md` の「運用」に書く。

### 知っておくこと（制約）
- 無料プランのため、しばらく使わないとサーバーが止まり、次に開いたとき表示まで時間がかかる（データは消えない）。
- 無料プランの条件（容量・止まるまでの時間など）は変わることがある。
- バックアップは自動ではないので、月1回自分でとる。
